# 第二版节点编辑器：抽屉、动作和作用范围

实现状态：本设计已在 `3.0.0-alpha.3` 接入实际 Go 程序，使用与验证见 [README.md](README.md)。以下保留设计阶段记录。

设计原型位于 `design/node-editor-v2.html`。直接打开即可体验，不需要服务或联网。设计稿只使用独立的 `d4-node-v2-design` 浏览器存储，不读写 `workspace.timeline.json`，不调用键鼠输入。本轮没有替换现有 EXE。

## 判断与依据

第一版把时间轴的属性面板留在了节点编辑器里，导致参数分散：按键和时长在节点上，坐标、取点、停用和宏设置在右侧。右侧主要是重复信息，却占据约 230px 画布。宏管理与节点库又共享左侧纵向空间，宏多了会挤压动作入口。

更影响使用的是执行模型：用户想表达的是“按住右键，同时连续点技能”，第一版要求先理解分叉、汇合、连线和宏循环。把并行和汇合换个图标不能解决这个问题，需要让作用范围可见。

参考材料（2026-11-07 查阅）：

- [ComfyUI 侧栏状态实现](https://github.com/Comfy-Org/ComfyUI_frontend/blob/main/src/stores/workspace/sidebarTabStore.ts)：`activeSidebarTabId` 只保留一个当前侧栏，同一按钮再次点击置空。借用工具入口常驻、内容互斥打开、再次点击收起的方式。
- [ComfyUI 子图说明](https://docs.comfy.org/interface/features/subgraph)：把相关节点打包成整体，支持嵌套和折叠；外露参数可以直接编辑。借用明确范围与整体操作。此文档描述的是子图组织，不是宏的并行或循环；下面的执行语义是针对本项目的设计。
- 本项目第一版源码与测试：动作参数重复、并行需要手动配对汇合、整段循环设置与画布范围分离；目前没有框选和局部重复。

这是一轮基于现有代码与参考界面的交互设计，尚未做真实用户可用性测试。

## 1. 工作台结构

左侧常驻约 64px 工具栏，只有宏、节点、帮助、设置四个入口。宏管理和节点库分别打开独立抽屉，互斥显示，再次点击收起。桌面抽屉占据自己的宽度，画布不会被遮住；窄窗口允许临时覆盖。切换抽屉不切换当前宏，不丢失选择和插入位置。

宏抽屉负责新建、切换与概览，当前宏名称在顶部常驻。重命名、复制、快捷键放到“宏设置”短对话框，避免编辑动作时看见整套管理表单。后续真实版补充删除宏、导入与录制入口；这些继续使用现有 Go 接口。

节点抽屉只显示点击、按住、等待、移动、滚轮五种动作，可以搜索、点击添加或拖入指定分支。抽屉底部显示“将接在哪个动作后”，避免插错范围。开始和结束由流程自动提供。

移除常驻右侧属性面板。按键、录入、时长、坐标、起点、取点回到节点；复制、停用、删除在节点菜单。较少使用的鼠标起点用节点内折叠区承载。流程状态放在顶部和预览栏，不再为这些信息单独开栏。

预览默认只有底部约 60px 播放条，可展开执行明细。显示整个流程总时长、当前进度，并高亮正在执行的节点；局部重复显示当前第几次。动作并行时可以同时高亮多个节点。

## 2. 五种动作的节点设计

| 动作 | 卡片默认显示 | 次要操作 |
| --- | --- | --- |
| 点击 | 按键、录入、按下时长 | 停用、复制、删除 |
| 按住 | 按键、录入、按住时长 | 停用、复制、删除 |
| 等待 | 等待毫秒数 | 复制、删除 |
| 移动 | 目标 X/Y、移动时长 | 起点折叠区、屏幕取点；录制轨迹保留 |
| 滚轮 | 滚动量及正负方向提示 | 停用、复制、删除 |

同一动作的所有配置在同一张卡片内。录制轨迹在真实版显示“保留 N 个点”，调整时长同时缩放点位时间；不让原型的直线移动代替已有轨迹。

连线是自动布局后的阅读辅助。每个连接中间有“＋”，可以直接插入动作并自动接好；常规使用不要求拖线。节点可以拖到同一顺序或另一分支重排，操作后立即重新计算时长。自由拖线可以以后作为高级功能，须遵守结构边界，不能绕过重复范围的入口与出口。

## 3. 同时执行：一个有分支的范围框

操作入口为选中后的“同时执行”，不作为第六种基础动作塞进节点库。

选中一个动作后，生成一个包含它的分支 A，以及一个空的分支 B。选中多个连续动作后，每个动作成为一条分支；原型用提示说明这次变化，撤销可恢复。需要保留一个顺序组合时，可先放到同一分支，再向其他分支加动作。

框头叫“同时执行”，内部按分支 A、B、C 分行。每个分支内部从左到右执行；所有分支同时开始；较短分支完成后等待其他分支。框底持续显示“同时开始 · 全部完成后继续”。汇合点自动生成，不需要用户创建、连入或管理。

增加分支后显示空落点，直接打开节点抽屉并把插入目标指向新分支。空分支时长为 0，不影响其他分支。删除非空分支要确认，允许撤销。真实版可上限 64 个分支，对应现有并发上限；原型为便于展示限制 8 个。

例如：

```text
开始 → 同时执行 ┌ 分支 A：按住右键 800ms                      ┐ → 等待120ms → 点击2 → 完成
                └ 分支 B：重复4次［点击1 60ms → 等待140ms］ ┘
```

两条分支都在 800ms 完成，因此等待 120ms 从 800ms 开始，点击 2 在 920ms 开始，总计 980ms。

## 4. 重复这一段：次数属于可见的范围

选中一个动作或同一顺序中的连续内容，点“重复这一段”。紫色外框包住选择内容，框头直接显示“重复 3 次”“两轮之间 0 ms”。末尾回到框内第一步的虚线在框内闭合，框外仍然只有一个入口和一个出口。

重复范围既能包动作，也能包整个同时执行框。反过来，一个分支也能包含重复范围。这样“右键一直按住，同时技能连点 4 次”和“左右两路一起执行 4 轮”会有不同的、可见的边框层级。

- 默认有限次数，原型允许 1–100 次，默认 3 次。
- 两轮间隔只发生在相邻两轮之间，最后一轮后直接继续。想在最后再等一次，应在框后放等待动作。
- 每轮都等范围内全部动作完成，再开始下一轮。
- 局部重复不提供无限模式。无限分支会使“全部完成后继续”永远无法成立，容易误解。持续运行由整个宏承担。
- 同时执行框和重复框均可收起，仍显示语义、动作/分支数与总时长。折叠只影响显示，不改执行内容。
- 菜单“改为顺序执行”是显式变换：并行的分支按 A、B、C 拼接，重复框展开为一次，时长随之改变；应显示结果提示并可撤销。

范围时长计算：顺序取和；同时执行取最长分支；重复取 `次数 × 范围时长 + (次数 − 1) × 两轮间隔`。

## 5. 整个宏持续循环：只在顶部设置

顶部一直显示“整个宏：执行一次 / 持续循环”。开启后，包含开始、所有步骤和结束的最外层虚线框出现，框头写“整个宏 · 持续循环”，结束卡变成“下一轮”，并显示每轮间隔。

这与局部的“重复 4 次”不同：前者作用于整个流程，后者只包围框内内容。每轮开始前上一轮必须完成。再按启动键停止；失焦和 Pause 继续服从原有 Go 内核规则。不能把停止按钮做成图中的普通节点，否则循环可能到不了停止步骤。

## 6. 选择、拖放与异常

点击选中一个动作，Shift 点选选择同一顺序里的连续范围；Shift 拖动空白框选。选中后显示画布上方的浮动操作条，避免遮挡框底的添加分支入口。点击范围标题选中整个范围，避免框选把不同分支的内容意外混在一起。

不允许在不同分支中跨越选择，提示分别选择或选择整个同时执行框。把动作移入其他分支是显式拖放；移动范围整体与移动框内动作区分。拖放目标高亮，放下后自动连接并重算；错误输入原子回滚。Delete 删除，Ctrl D 复制，Ctrl Z 撤销，Ctrl Shift Z 重做。

空白拖动平移、滚轮围绕指针缩放。移动卡片改变顺序时必须显示插入指示；纯粹视觉整理不应悄悄改变时序。这版采用自动结构布局，省去手动摆放和修复交叉线。

## 7. 如何接入 Go，而不增加运行时编辑开销

交互稿用结构树：`sequence / parallel / repeat` 与五种动作。建议真实版采用 `graph.version = 2` 存储相同结构；它是执行结构，视觉范围不会成为独立于执行语义的装饰信息。

Go 仅在加载、保存、应用时编译结构树为带绝对时间的动作，然后继续使用已有事件编译器、输入所有权与调度内核。运行中不解释 UI 节点。

- 顺序累加开始时间，并行复用开始时间并取最大结束时间。
- 有限重复展开动作；在展开前做次数、最大时长、展开事件数检查，检查有界乘法，避免先分配巨大数组。
- 保留现有最多 1 小时、最多 100000 个事件、输入释放和并行移动冲突规则。重叠的鼠标移动仍应拒绝，而不是简单按分支顺序覆盖。
- 两轮间隔只加在重复范围之间；同键交叠继续使用现有引用计数。总时长包含最后等待与停用动作占用时间。
- 折叠状态单独存为视图数据，不能修改编译结果。

此轮原型的计时仅用于设计验证，不等同于上述 Go 接入已经完成。没有新建真实执行格式、没有修改生产编译器。

## 8. 旧配置迁移与落地次序

时间轴 schema 3 可以按当前方法保持绝对时序地转成并行分支，再生成结构树。第一版任意 DAG 不一定可以准确表达为嵌套结构；能证明是单入口、单出口的顺序 / 并行区域才自动转换，转换前后要对比完整事件计划。

不可化简的交叉依赖保留原图与原执行计划，提示进入兼容编辑方式；不可猜测性重排，不能因美化界面改变旧宏。新建宏使用结构模型，保存前保留原文件。旧程序遇到 `graph.version = 2` 必须明确拒绝，避免丢失局部循环语义。

建议先确认交互稿，再依次接入抽屉与节点内参数、结构编译器及迁移、真实录制与执行验证。无需重新重构事件调度内核。
